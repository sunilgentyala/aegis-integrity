# Directory listings

AEGIS is published as source on GitHub and as a package on PyPI. It is also listed in two third-party MCP directories. Neither directory hosts or runs AEGIS: the server always runs on your own machine over stdio, and documents never leave it. This page records what each listing is, what its status means, and how it was set up.

Last checked: 2026-10-16 (AEGIS v3.3.2).

## What the statuses do and do not mean

- Both statuses mean the repository owner controls the listing. They do not mean either directory audited AEGIS or endorses it.
- The mcprush grade and trust score, and the Glama maintenance rating and discovery score, are each directory's own automated results. They can change without any change to AEGIS.
- The mcprush "verified" badge in the README is a static badge that links to the listing. mcprush does not publish an embeddable badge. The Glama badge is the official one.
- Download numbers shown on mcprush come from PyPI. The directory is a place to find AEGIS, not the source of the installs.

## Glama build settings

Glama builds the server from the repository in a Debian container with a `uv`-managed Python. Settings that work:

| Setting | Value |
|---|---|
| Python | 3.11 |
| Build step | `uv pip install --python /usr/local/bin/python --break-system-packages --no-cache '.[ml,nlp,bib,mcp]'` |
| Command | `python aegis_mcp.py` (run behind `mcp-proxy`) |

Plain `pip` is not available in that image, `uv pip install --system` targets Debian's own Python, and the `uv`-managed Python refuses installs unless `--break-system-packages` is given, which is safe in a throwaway build container. The repository also ships `Dockerfile.mcp` (stdio MCP server image) and `glama.json` (maintainer list).

## Which one to use

Use the PyPI package or the GitHub repository for production use. Use the directory pages for discovery, release notes and community reviews. If a directory page and the repository disagree, the repository and PyPI are authoritative.
